## Astryx (Meta), CLI 0.7.16 read locally, site read in Chrome
- Latest stable 0.7.16 (14 Nov 2026); 0.7.11 to 0.7.16 shipped 7 to 14 Nov; canaries daily. Peer: React >=19, StyleX ^0.19. [npm]
- Counts in 0.7.16: 174 components, 7 bundled themes (only neutral maintained), 784 templates = 58 page + 726 block. [CLI]
- llms.txt says: use the CLI instead of crawling pages; "agent ready" positioning; "powers over 13,000 apps" inside Meta. [astryx.atmeta.com/llms.txt]
- Principles: components over primitives; semantic tokens; theme-agnostic code; open internals. 8 rules incl. frame-first layout, dense data as rows not cards, controlled inputs, router-agnostic links (useLinkComponent). Anti-patterns list (inline styles, hex, px, raw <a>, card-wrapping everything, Badge as decoration, inventing props). [docs principles]
- is-my-code-good: evidence-based review; every claim cites route/file/line/rendered state; categories good / needs work / not inspected; "never turn missing evidence into a pass"; compare sibling surfaces; render empty/loading/error/long-content states at narrow and wide widths in every colour mode. [docs is-my-code-good]
- Working with AI: `init --features agents` writes a marked block into AGENTS.md / CLAUDE.md / GEMINI.md, refreshed by `upgrade`; 3-step agent workflow build -> template -> component; global skill via `init --user`; per-tool targets. [docs working-with-ai]
- Spacing in rem (0.25rem steps) "so gaps and padding grow with the reader's browser font size the way text does"; 15 tokens 0 to 3rem; gap props take steps. [docs spacing]
- Colours use CSS light-dark(); radius tokens scale by a theme radius multiplier; motion knobs: tempo 0.75 to 1.5 scales durations, character crisp/standard/expressive sets entrance/move curves; Reduce Motion caps at 200ms (not zero); dedicated focus-ring tokens; data-viz tokens: categorical per series + neutral + sequential ramps 5..1; type scale round(14 x 1.2^step). [docs tokens]
- Layout guide: outside-in (scaffold shell and region budgets, structure, spacing, breakpoints per region: divide, reveal, resize or swap). [docs layout]
- Skill check vs 0.7.16: counts and CLI path correct. Missing: experimental theme editor workflow (`experimental theme editor new/set/how/show --png`, "a theme change is not done until you have looked"), `swizzle`, `discover`, `manifest`, `--zh`/`--lang`. init flags match.

## Material 3 (Google)
- Three token classes: reference (raw), system (semantic), component (e.g. md.comp.fab.primary.container.color); names describe how/where used; names stay when values change; token "contexts". [m3.material.io/foundations/design-tokens/overview]
- Motion: physics (spring) system introduced May 2025 with M3 Expressive, "replacing the previous system based on easing and duration"; two schemes, expressive (overshoot, default) and standard (minimal bounce, utilitarian). Web: "compatible with Compose springs, see specs". [m3.material.io/styles/motion/overview/how-it-works]
- @material/web 2.5.0 (17 Nov 2026). [npm]

## Apple HIG
- Every page uses one structure: Getting started, Best practices, Platform considerations, Resources, Change log (dated). [developer.apple.com/design/human-interface-guidelines/writing]
- Writing: decide the app's voice, vary tone by context, keep a list of common terms for consistency; errors next to the field, say how to fix, not what not to do; avoid robotic messages like "Invalid name". [same]

## Primer (GitHub)
- Accessibility hub: Foundations, Design guidance, Copilot Accessibility Principles, Annotation Toolkit, Accessibility for Primer UI, Accessible messaging. [primer.style/accessibility]
- Copilot Accessibility Principles (for generative and agentic AI): 1 Clear and understandable (plain language, structured output, essentials by default with expand for more, feedback near focus); 2 Transparent and predictable (announce actions and intentions, make clear who is speaking and what is generated, separate user messages / replies / reasoning / generated content, identify each agent and transitions, status that works with assistive tech, confirm changes took effect); 3 Adaptable (control speed, detail, format, autonomy; no time limits; multiple input methods; saved preferences; icebreaker prompts); 4 Flexible and forgiving (review, correct, reverse; keep a record; make changes clear; explain problems and next steps; preserve progress; regain context after a break); 5 Consistent and reliable (no unexpected focus shifts or layout movement). Use: ask Copilot to evaluate specs against them, annotate designs, critique in reviews. Grounded in research with assistive-technology users. [primer.style/accessibility/foundations/copilot-principles]
- @primer/react 38.46.0 (17 Nov 2026). [npm]

## Atlassian
- Token names read foundation.property.modifier (color.text, color.icon.success, color.background.danger hovered); separate colour tokens for text, links, icons, backgrounds, borders, blankets, charts, skeletons; opacity tokens (opacity.disabled, opacity.loading). Themes cover light, dark, high contrast, and non-colour themes (density cozy/comfortable/compact, reduced motion, typography). Do: pick tokens by meaning; Don't: pick a token because the colour matches. [atlassian.design/foundations/tokens/design-tokens]
- Release phases: Early Access (0.x, breaking changes possible), Beta (1.0+, breaking only in majors), General Availability; deprecation phases: Intent to Deprecate (Caution), Deprecated (removed after the period, alternative given). [atlassian.design/release-phases]
- Has a dedicated "Rovo UI" section for its AI. @atlaskit/tokens 20.13.0 (17 Nov 2026). [site nav, npm]

- Two token layers: global (context-agnostic raw values, also type, radius, stroke, animation) and alias (semantic; composite aliases condense shadows and type into one). Out of the box: light, dark, high-contrast and branded themes, with contrast ensured. [fluent2.microsoft.design/design-tokens]

## GOV.UK Design System
- To propose: Useful (evidence many teams/services would use it: screenshots or links) and Unique (does not replicate; if replacing, evidence it is better). To publish: Usable (tested in user research with a representative sample including disabled people; contexts tested stated), Consistent (reuses existing styles and components; guidance follows the style guide; code meets Frontend standards), Versatile (works across services; tested across browsers, assistive tech, devices). Community tools need a clear owner, support within 1 month, no more than 3 months behind. [design-system.service.gov.uk/community/contribution-criteria]
- govuk-frontend 6.6.0 (15 Oct 2026). [npm]
